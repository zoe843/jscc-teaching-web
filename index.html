1.1 分贝 dB：通信人的「科学计数法」

为什么需要 dB：信噪比的真实比值可以从 0.0001（噪声是信号一万倍）跨到 10000（信号是噪声一万倍）。直接写比值，数字要么巨长要么巨碎。取对数压缩一下：10^-4 到 10^4 变成 -40 到 40，好写好画好比较。

式 1-1 · 分贝定义功率比值取以 10 为底的对数再乘 10
\text{SNR}_{\text{dB}} = 10\log_{10}\!\left(\dfrac{P_{\text{信号}}}{P_{\text{噪声}}}\right) \quad\Longleftrightarrow\quad \dfrac{P_{\text{噪声}}}{P_{\text{信号}}} = 10^{-\text{SNR}_{\text{dB}}/10}

左边是定义（dB 往回变倍数），右边是它的反解——算法 1-2 里那行 10 ** (-snr_db / 10) 的全部来历，就这一行公式。

SNR (dB)信号 : 噪声功率体感本项目里
0 dB1 : 1一半能量是信号，一半是噪声实验区下限附近
3 dB≈ 2 : 1+3dB ≈ 功率翻倍（精确 1.995）—
10 dB10 : 1+10dB = ×10训练主战场
20 dB100 : 1+20dB = ×100实验区上限，基本清晰
-3 dB≈ 1 : 2负数=信号比噪声还弱悬崖效应演示区

手算三连（拿出纸，做完再看答案）：① SNR=6dB，噪声功率是信号的几分之几？② 实测 E[n²]=0.01（信号功率 1），SNR 是多少 dB？③ SNR 从 10dB 掉到 0dB，噪声功率变了几倍？

手算三连的答案
① 10^(-6/10) ≈ 0.25，四分之一（6dB ≈ 两个 3dB：×2 再 ×2）。② SNR = 10·log10(1/0.01) = 20dB。③ 噪声/信号 从 0.1 变成 1，变 10 倍——「掉 10dB = 噪声功率 ×10」，跟表格里「+10dB = ×10」是同一句话反过来。
🎓 为什么是乘 10 不是乘 20？ dB 的定义对功率比用 10log10，对幅度比（电压/声压）用 20log10——幅度平方才是功率，多出来的平方在对数里变成 ×2。本项目公式里全是功率，一律乘 10。通信原理课会正式推，这里记住「功率用 10」防混淆即可。

1.2 随机数与概率：最小套装（四个词）

信道噪声是随机的，所以本章绕不开四个概率词。每个都用你已经写过的代码来定义：

词人话定义代码里的样子
期望 E[X]取值按概率加权的平均；样本够多时 = 直接求平均np.mean(x)
方差 σ²「偏离平方」的平均 E[(X−μ)²]，衡量波动大小np.mean((x-mu)**2)
标准差 σ方差开根号，「典型偏离幅度」（跟原值同单位）np.sqrt(np.var(x))
高斯/正态分布钟形曲线：中间密两头稀，σ 越大越矮胖rng.normal(0, σ, N)

你在单元4 写过 rng.normal(0, sigma, n_bits)——现在用概率语言重述：从均值 0、标准差 σ 的高斯分布里抽 n_bits 个样本。四个新认识：

  1. 噪声功率 = 方差：均值 0 时，E[n²] = Var(n) = σ²。「噪声的平均平方值」在概率课叫方差、在通信课叫功率——1.3 节正式把两个课的词接上。
  2. 大数定律：样本够多时实测平均 → 理论值。跑码件第 3 节造 100 万个噪声点，实测功率 0.1001 ≈ 理论 0.1，就是它。
  3. 固定种子：np.random.default_rng(42) 里的 42 是种子——同一颗种子每次运行生成同一串「随机」数。随机的是分布，不随机的是实验的可复现性。
  4. 复高斯 CN(0,1)：通信噪声天然带两个维度（同相 I + 正交 Q），记作 n \sim \mathcal{CN}(0,1)，含义 = 实部、虚部各一个独立的 N(0,1/2)，两部分功率相加才是 1。本教程教学版全用实数符号；复数版只是每步拆成两份，想上再回来。

1.3 功率：为什么 E[x²] 叫「功率」

信号与系统的说法：阻值 1Ω 的电阻上，瞬时功率 P = v²/R = v²。所以对一串信号值，「每个值平方」就是「瞬时功率」，取平均 E[x²] 就是「平均功率」——没有更多物理，就是平方求平均。三件事一次钉死：

  1. 信号功率 = E[s²]（符号平方的平均）。功率归一化的目标就是让它 = 1。
  2. 噪声功率 = E[n²] = σ²（高斯、均值 0 时，方差就是平均功率）。
  3. SNR = 两者之比，按式 1-1 换成 dB。整条链：归一化 → σ² 有定义 → SNR 有定义 → 曲线能画。
🎓 C 类比 E[x²] 就是一个 for 循环：for(i) acc += x[i]*x[i]; power = acc/N;。「期望」「平均」「均值」三个词在代码里都是这个循环。

单元4 仿真的骨架（回忆）你已经写过的一维 BPSK 链路 · 下面表格逐行拆
bits = np.random.randint(0, 2, n_bits)      # ① 信源：随机比特
symbols = 1 - 2 * bits                       # ② 映射：0→+1, 1→-1
noise = rng.normal(0, sigma, n_bits)         # ③ 信道：加高斯噪声
received = symbols + noise                   #    y = x + n
decoded = (received < 0).astype(int)         # ④ 判决：负号判 1
ber = np.mean(decoded != bits)               # ⑤ 统计误码率
行逐行拆解
① randint在 [0, 2) 半开区间抽整数 = 只有 0 和 1，抽 n_bits 个。Python 区间左闭右开的老规矩。
② 1-2*bits一行算术完成映射：bits=0 → 1-0=+1；bits=1 → 1-2=-1。紧凑但没毛病——拆开写就是 if bits==0: s=+1 else: s=-1 的向量化。
③ normal三个参数 = (均值, 标准差σ, 个数N)。注意第二个参数是 σ 不是 σ²——1.2 节的词：抽 N 个高斯样本。
④ 相加两个同形状数组逐元素相加，就是 y = x + n 本尊。
⑤ astypereceived < 0 先得到一个 True/False 数组，.astype(int) 把 True→1、False→0。「判决」就是这一比。
⑥ mean(≠)decoded != bits 又是一个布尔数组（错=True），对布尔数组求 mean = True 的占比 = 误码率。这个「布尔直接求平均」的紧凑写法值得单独记住：布尔在 NumPy 里就是 0/1。
🎓 关键转变：把「一步」换成「一个网络」 BPSK 里 ② 的映射是人为规定的（0→+1）；JSCC 里这个映射换成训练出来的神经网络（编码器）。④ 的判决换成另一个网络（解码器）。③ 的信道——加高斯噪声——一行都不用变，它就是你写过的那行 x + noise，只不过从 NumPy 搬进 PyTorch。这就是整个项目的骨架，没有更多了。

1.5 换个信源：不先变成比特，怎样完成压缩和传输？

传统链路的信源编码思路：图像 → JPEG 压缩成比特 → 比特过信道。这里有一个通信原理里的根本假设——香农分离定理：只要码长无限长，信源编码和信道编码可以分开设计、各自最优，合起来也不损失。

但现实不给你无限码长。实际系统块长短、时延受限，固定码率的数字链路在实际信道差于设计条件时，可能出现信道译码失败，进而导致源解码质量骤降，称为悬崖效应。错误保护、码率自适应和渐进编码会影响这种行为，不能把所有分离式系统都描述为“一错就全毁”。

本页模拟 Deep JSCC 的思路：把压缩与抗噪编码放进同一个可学习映射，不先生成单独的压缩比特码流，而是把图像映射成一组连续实数符号过信道。失真从「整块崩坏」变成「随 SNR 平滑劣化」——下面这个交互是这个项目的题眼，拖一下 SNR：

1.7 功率归一化：过信道前的必经一步

信道的噪声强度由 SNR 定义，而 SNR = 信号功率 / 噪声功率。如果编码器输出的符号忽大忽小，SNR 就无从定义——所以发射前必须把符号功率归一到 1（通信原理里的「平均功率约束」落进代码就是这一步）。

算法 1-1 · 功率归一化把每张图的符号平均功率约束到约 1
s_{\text{norm}} = \dfrac{s}{\sqrt{\tfrac{1}{k}\textstyle\sum_{i=1}^{k} s_i^2 + \varepsilon}}
符号含义代码里叫
s编码器输出的 k 个原始符号s
\tfrac{1}{k}\sum s_i^2符号的平均功率（均方值 RMS²）torch.mean(s**2, dim=1, keepdim=True)
\varepsilon防除零的小量 1e-8（工程习惯）eps

手算一遍（老规矩，勾股数最友好）：符号 [3, 4]，平均功率 = (9+16)/2 = 12.5，RMS = √12.5 ≈ 3.54，归一化后 ≈ [0.85, 1.13]。验证：0.85² + 1.13² ≈ 2 → 每符号平均功率 = 2/2 = 1 ✓。

channel.py · power_norm5 行。注意 keepdim=True 是为了让除法广播对齐
def power_norm(s, eps=1e-8):
    # s: (B, k)  编码器输出的原始符号
    rms = torch.sqrt(torch.mean(s ** 2, dim=1, keepdim=True) + eps)
    return s / rms
🎓 C 类比 这就是一个按行归一化的 for(i=0; i<B; i++){ rms=sqrt(sum(s[i]^2)/k); for(j) s[i][j]/=rms; }——PyTorch 的 broadcast 把内层循环隐掉了。你在位置编码广播可视化（transformer-course-web 交互 3b）里见过同一套广播规则。

1.8 AWGN 信道层：你写过的那行 x + noise 搬进 PyTorch

先解决换算：SNR 用 dB 表示时，噪声方差怎么算？ 定义 SNR(dB) = 10·log₁₀(P/σ²)，信号功率归一化后 P=1，反解：

算法 1-2 · AWGN 信道加性高斯白噪声，唯一要算的就是 σ²
\sigma^2 = \dfrac{P}{10^{\text{SNR}_{\text{dB}}/10}}, \qquad y = s + n,\quad n \sim \mathcal{N}(0, \sigma^2)

手算：SNR = 10 dB → σ² = 1/10¹ = 0.1；SNR = 0 dB → σ² = 1（噪声功率=信号功率，对半分）；SNR = 20 dB → σ² = 0.01。本页实数功率比定义下，sigma = 10 ** (-snr_db / 20) 是同一个换算的 σ（不是 σ²）版本；复用单元 4 前另查它是否用 Eᵦ/N₀，见 3.4 的 3 dB 换算——注意开没开根号，这是最常见的手滑点。

channel.py · AWGNChannel实数 AWGN · P=1 的固定发射功率约定
class AWGNChannel(nn.Module):
    def forward(self, s, snr_db):
        # s: (B, k) 已归一化，平均功率 ≈ 1
        sigma2 = 1.0 / (10 ** (snr_db / 10))
        sigma = sigma2 ** 0.5
        noise = torch.randn_like(s) * sigma
        return s + noise

1.9 瑞利衰落：两个高斯分量合成一个幅度

AWGN 模型把信道增益固定为 1；多径环境中的增益还会随机变化。多条路径叠加时，有时增强、有时抵消。瑞利模型适合没有明显主导直射分量的散射环境；有较强直射的卫星或地面链路常考虑莱斯模型，不能简单把“卫星”等同于“瑞利”。

算法 1-3 · 归一化瑞利幅度
a,b\overset{\mathrm{iid}}\sim\mathcal N(0,1)
h=\sqrt{(a^2+b^2)/2},\qquad E[h^2]=1
y=hs+n,\qquad y_{\mathrm{eq}}\approx y/h=s+n/h

a 和 b 是两个独立方向的高斯分量。平方相加开根号才得到瑞利幅度；除以 √2 保证总平均功率为 1。|N(0,1)| 是半正态分布，不是瑞利分布。只验证 E[h²]=1 不足以判断分布是否正确，还要看均值或深衰落概率。

代数值：a=0.6、b=0.8，则 h=√(1/2)≈0.707；若发送 s=1、噪声 n=0.1，接收 y≈0.807，除以 h 后约 1.141。均衡修正了信号增益，却把噪声从 0.1 放大到约 0.141。若 h=0.1，噪声标准差放大 10 倍，方差放大 100 倍。

明确教学假设本页使用“实数符号＋瑞利幅度＋理想相位补偿”的简化模型；每张图采一个 h，图内 k 个符号共享 h，称为块衰落。接收端假设知道 h（理想 CSI）。完整复信道还含随机相位与 I/Q 噪声，不能把本例声称为完整复基带复现。
channel.py · RayleighChannel · 教学参考片段
class RayleighChannel(nn.Module):
    def forward(self, s, snr_db):
        B, k = s.shape
        a = torch.randn(B, 1, device=s.device, dtype=s.dtype)
        b = torch.randn_like(a)
        h = torch.sqrt((a ** 2 + b ** 2) / 2.0)
        sigma = 10.0 ** (-snr_db / 20.0)
        noise = torch.randn_like(s) * sigma
        y = h * s + noise
        y_eq = y / h.clamp_min(1e-6)
        return y_eq

第 1 章自测
(B, 3, 32, 32) 从左到右每个数是什么？一共多少个数值？
B=batch 一次几张图、3=RGB 通道、32×32=高×宽。一张图 3×32×32=3072 个数，B 张就是 B×3072 个。这题不过关别进第 2 章。
SNR=6dB 时噪声功率是信号的几分之几？SNR=-10dB 呢？
6dB：10^(-0.6)≈0.25（两个 3dB：×2×2）；-10dB：10^(1)=10 倍——信号功率只有噪声十分之一；本页滑块范围 0–20 dB，未覆盖这个值。
「σ² 叫噪声功率」和概率课的「方差」是什么关系？
同一个东西。高斯、均值 0 时 E[n²]=Var(n)=σ²：通信课管 E[n²] 叫平均功率，概率课管它叫方差。1Ω 电阻上 v² 就是功率，所以「平方的平均」=「平均功率」。
np.mean(decoded != bits) 为什么算出来是误码率？
decoded != bits 是布尔数组（错=True），布尔在 NumPy 里当 0/1 用，mean 就是 True 的占比 = 错的比例。紧凑但常用，值得单独记住。
SNR = 3 dB 时 σ² 是多少？SNR = -3 dB 呢？
10^(3/10) ≈ 2 → σ² = 1/2 = 0.5；10^(-3/10) ≈ 0.501 → σ² ≈ 1.99（噪声功率约为信号 2 倍）。负 dB 在 JSCC 实验里是常客（低 SNR 正是主战场），别觉得奇怪。
为什么 BPSK 有「判决」这一步，JSCC 没有？
BPSK 的符号只有 ±1 两个合法值，判决=挑最近的那个，一旦判错信息全丢（硬损失）；JSCC 的符号是连续值，接收端不猜「是哪个」，而是让解码器带着噪声信息去做软恢复——错多少修多少，这正是平滑退化的来源。
功率归一化去掉会怎样？模型不也能训练吗？
能训练，但 SNR 就失去意义了：网络会学会把符号幅度放大来「压制」噪声（等效作弊），不同 k/n、不同训练轮次之间完全不可比，PSNR-SNR 曲线没法画。功率约束是让实验「讲道理」的锚。
瑞利信道里「理想 CSI 均衡」的假设去掉会怎样？
y/h 做不了，解码器必须自己从信号里估计 h（盲均衡）或同时估计信道与内容——也可以利用导频估计 h，但要计入开销与估计误差。本页理想 CSI 是明确的教学简化，并不意味着所有论文采用相同假设。

2.0.1 nn.Module：自己组装一个网络（从零）

先看一个能跑的最小玩具——「输入 3 个数 → 输出 1 个数」的模块，每个部件标了编号：

nn.Module 最小样例V0 的编码器/解码器就是把这个骨架放大，结构一模一样
import torch.nn as nn

class ToyNet(nn.Module):              # ① 继承 nn.Module
    def __init__(self):               # ② 构造函数：摆零件
        super().__init__()            # ③ 先让父类完成初始化（必须！）
        self.fc = nn.Linear(3, 1)     # ④ 摆一个零件（可训练）

    def forward(self, x):             # ⑤ 定义数据怎么流
        return self.fc(x)             #    零件串起来

net = ToyNet()                        # ⑥ 实例化（此刻 fc 的权重已随机初始化）
print(list(net.parameters()))         # ⑦ fc 的权重和偏置自动登记在案
🎓 C 类比 一个 nn.Module ≈ 一个 struct：__init__ 是 malloc+成员初始化，self 就是 this 指针，forward 是对结构体的操作函数，super().__init__() 是先调父类的构造函数（C 里没有继承，但「先初始化基座再填自己的成员」的心智模型一样）。nn.Sequential(a, b, c) 则是一个「零件串联盒」：把几个零件排进盒子，forward 时自动依次过——等价于手写 return c(b(a(x)))。

2.0.2 形状操作五件套（含一个无声错误）

第 1 章你已经会 unsqueeze 和广播。本章代码卡新增五个操作，全部先在跑码件里玩过（demos/demo_ch2_tensor_toys.py，2.9 节有完整输出）。这里把行为规则逐个钉死：

操作规则本章哪里用
x.reshape(2, -1)重排成指定形状；-1 = 这一维自动算（总数÷其余维）。元素总数不变，按新形状组织；步幅兼容时可返回视图，否则可能复制，不能保证始终零拷贝编码器 4096、解码器 reshape 回 (B,256,4,4)
feat.unsqueeze(0)在指定位置插一根长度为 1 的轴：(2,)→(1,2)SNR 特征拼进 batch
fb.expand(8, -1)把 size=1 的轴复制放大成 8；-1 = 这维保持不动。不复制内存（共享），只读安全同上：(1,2)→(8,2)
torch.cat([a, b], dim=1)沿指定轴拼接：除 dim 外其余维必须同形(B,k) 拼 (B,2) → (B,k+2)
mean(dim=1, keepdim=True)dim=1 = 沿第 1 轴压掉；keepdim=True = 被压的轴留一根 size=1 的，方便下一步广播功率归一化（算法 1-1）
⚠️ 广播陷阱：忘写 keepdim，可能报错也可能静默算错 功率归一化里如果写成 torch.mean(s**2, dim=1)（丢掉 keepdim），得到 (B,)。当 B=k 时，(B,k) ÷ (B,) 恰好能广播，因此不报错——PyTorch 按列广播，第一列全除以第 0 个样本的 RMS、第二列全除以第 1 个样本的 RMS……每一行混着别的样本的功率，结果错得无声无息。跑码件第 4 节实测：按“除均方值”这个广播玩具，该得 [0.24, 0.32] 的一行变成了 [0.24, 1.6]（这里故意未开根号，实际 power_norm 除的是 RMS）。「报错的坑」好修，「不报错的坑」靠实验对照才抓得住——一般 B 与 k 不同且都大于 1 时会报尺寸不匹配；B=1 时又可能碰巧算对。所以要验证一般形状并保留 (B,1)，不能只试一个样本。

dim= 到底怎么数：张量的轴从外往里数 0,1,2……(B,3,32,32) 的 dim=0 是「批」、dim=1 是「通道」。mean(dim=1) = 把通道轴压掉（对每个位置跨通道求平均）。压掉的轴默认消失，keepdim 让它以 size=1 留下来。

2.0.4 训练五连：每一步在干什么

训练五连（骨架）本页采用的顺序；zero_grad 也可放在前向之前，但须在本次 backward 前清除旧梯度
x_hat = model(x, snr_db)   # ① 前向：算出预测
loss = loss_fn(x_hat, x)   # ② 算误差（一个标量张量）
opt.zero_grad()            # ③ 清空梯度账本
loss.backward()            # ④ 反向传播：算出每个参数的梯度
opt.step()                 # ⑤ 按所选优化器的规则更新参数
  1. ① 前向：数据流过 2.6 组装的流水线，得到重建图 x̂。
  2. ② loss：MSE 逐像素差方平均，得到一个标量张量。注意它不是普通数字，而是带着整条计算路径的「活账本」——第 ④ 步全靠它记账。
  3. ③ zero_grad：PyTorch 的梯度默认累加（你在 bp_demo 推过的机制：多路径梯度汇总就是这么实现的）。不清账，本批梯度会叠上上一批的——模型越训越疯且查不出原因。所以每批开头先清。
  4. ④ backward：从 loss 沿计算图反向走一遍，计算 loss 对每个参数的梯度；梯度指向局部上升方向，最简单的梯度下降沿其反方向更新。你 YOLO 文档第 6 章手推过两层网络的反传，这里只是交给框架自动做。
  5. ⑤ step：更新交给优化器决定。最简单的 SGD 可写成 θ ← θ − lr × 梯度；第 2.7 节使用的 AdamW 会利用历史梯度的一阶、二阶矩估计和偏差修正，并施加解耦权重衰减，因此不能直接套用这条 SGD 公式。lr=1e-3 是学习率；该训练片段未显式设置 weight_decay，采用 AdamW 默认值 0.01。

两个附属问题：loss.item() 把标量张量变回普通 Python 数（只取数值、甩掉计算图——统计用，省显存）；model.train() / model.eval() 是训练/推理模式开关——本模型没有 BN 和 Dropout，不写也能跑，但建议写上养成习惯（YOLO 里有 BN，忘了切 eval 会出诡异结果）。

2.0.5 设备与输出：.to(DEVICE) 和 f-string

设备：CPU 和 GPU 是两块独立内存，张量和模型必须待在同一块上才能运算。DEVICE = "cuda" if torch.cuda.is_available() else "cpu" 检测后，model.to(DEVICE) 和每个 batch 的 x.to(DEVICE) 把两者搬到同侧。忘搬其中一边，报错形如 Expected all tensors to be on the same device——看到它就回来查这节。SNR 特征是现造的小张量（CPU 出身），所以 2.4 代码卡里那句 .to(s.device) 是必备保险。

f-string 拆解（训练日志那行）：f"epoch {epoch} loss {total / len(loader):.5f}" —— 引号前的 f 表示「花括号里是变量」：{epoch} 直接填值；{total / len(loader):.5f} 花括号里可以是表达式，:.5f 表示格式化成小数点后 5 位。拆成普通写法 = "epoch " + str(epoch) + " loss " + str(round(avg, 5))——f-string 只是省事，不是新语言。

2.1 自编码器：从零定义

自编码器（autoencoder）= 一个「压缩-还原」网络：编码器把输入压成一个低维表示（瓶颈），解码器从瓶颈还原输入，训练目标 = 还原得像不像（重建误差）。JSCC 的巧妙之处：把信道插在瓶颈处——压缩后的符号必须先扛过噪声，才能被还原。于是网络被迫学会「把重要的信息编码得更抗噪」。这就是「语义」长出来的机制。

🎓 类比：传话游戏 But 训练过 3072 个像素值 →（编码器）→ 256 个数 →（信道：被噪声污染）→（解码器）→ 3072 个像素值。就像让一个人用 256 个词描述一张图，另一个人照着画回来——中间传话还会走样。训练 = 反复练习，让「描述的方式」尽量抗走样。

2.2 卷积与转置卷积：缩小靠前者，放大靠后者

普通卷积（缩小方向）——你在 YOLO 源码的 cv1/cv2 里天天见的 nn.Conv2d，参数五件套 (in_ch, out_ch, kernel, stride, padding)：kernel×kernel 的窗口在图上滑动，每停一处做一次加权和输出一个数。本章只用三个事实：

  • stride=2 = 窗口每次跳 2 格 → 输出边长减半（32→16→8→4），同时通道数由 out_ch 说了算（3→64→128→256）——空间变小、通道变多，「空间换特征」；
  • padding=1 = 图四周补一圈 0，配合 kernel=4 才能让「减半」除得整整齐齐（4/2/1 组合的另一半）；
  • 窗口里的加权和系数全是可训练参数——YOLO 文档讲过的卷积三层账在这里原样成立。

转置卷积（放大方向）——解码器要把 4×4 放回 32×32，需要「放大器」。先看固定的放大怎么做：最近邻插值——每个像素复制成 2×2 四份，4×4 立刻变 8×8，但它是个死规则，没有参数可学。转置卷积 = 把这个放大器做成可学习的：

class EncoderV0(nn.Module):
    def __init__(self, k):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(3, 64, 4, stride=2, padding=1),    # → (B,64,16,16)
            nn.ReLU(inplace=True),
            nn.Conv2d(64, 128, 4, stride=2, padding=1),  # → (B,128,8,8)
            nn.ReLU(inplace=True),
            nn.Conv2d(128, 256, 4, stride=2, padding=1), # → (B,256,4,4)
            nn.ReLU(inplace=True),
        )
        self.fc = nn.Linear(256 * 4 * 4, k)

    def forward(self, x):
        h = self.conv(x)                # (B,256,4,4)
        h = h.reshape(h.size(0), -1)    # (B,4096)
        return self.fc(h)               # (B,k)

2.4 SNR 注入：让解码端知道信道有多差

人在听含糊的录音时会自动「更用力猜」；解码器面对被噪声污染的符号，恢复策略也应该随噪声强度变化——所以要把 SNR 作为一个输入告诉解码器。本教程采用一种简单设计：把线性 SNR 的倒数和它的对数拼进解码器输入。两者由同一个 SNR 算出，不增加独立信息，也不是所有 JSCC 论文的标准接口。这里假设接收端已知该 SNR。

算法 2-2 · SNR 特征两个标量：线性域倒数 + 对数域（量纲互补）
\text{feat} = \left[\, 10^{-\text{SNR}_{\text{dB}}/10},\; \log_{10}\!\big(10^{-\text{SNR}_{\text{dB}}/10}\big) \,\right] \in \mathbb{R}^2

SNR=10dB → [0.1, −1]。为什么两个都要？线性倒数给「噪声大小」的绝对量级，对数给「跨数量级」的等距感（5dB 和 10dB 在对数域一样远）——网络对两种感受都要用。手算：SNR=0dB → [1, 0]；SNR=20dB → [0.01, −2]。

import math

def snr_features(snr_db):
    inv = 10 ** (-snr_db / 10)                    # 标量 1/SNR（线性）
    feat = torch.tensor([inv, math.log10(inv + 1e-8)])
    return feat                                    # (2,)

class DecoderV0(nn.Module):
    def __init__(self, k):
        super().__init__()
        self.fc = nn.Linear(k + 2, 256 * 4 * 4)
        self.deconv = nn.Sequential(
            nn.ConvTranspose2d(256, 128, 4, stride=2, padding=1), # → (B,128,8,8)
            nn.ReLU(inplace=True),
            nn.ConvTranspose2d(128, 64, 4, stride=2, padding=1),  # → (B,64,16,16)
            nn.ReLU(inplace=True),
            nn.ConvTranspose2d(64, 3, 4, stride=2, padding=1),    # → (B,3,32,32)
            nn.Sigmoid(),
        )

    def forward(self, s, snr_db):
        feat = snr_features(snr_db).to(s.device)
        feat = feat.unsqueeze(0).expand(s.size(0), -1)
        z = torch.cat([s, feat], dim=1)          # (B,k+2)
        h = self.fc(z)                            # (B,4096)
        h = h.reshape(-1, 256, 4, 4)              # (B,256,4,4)
        return self.deconv(h)                     # (B,3,32,32)
⚠️ 高频坑：两头值域咬合 torchvision 的 ToTensor() 把 PIL 图变成 [0,1] 浮点张量——不要再加 Normalize（那会把值域挪到 ±2 左右，而 Sigmoid 输出永远在 (0,1)，loss 降不下去且你查不出哪错了）。你 YOLO 教程第 4 章见过 ultralytics 的归一化是 /255，同一个道理：先确认两头范围一致。

class JSCC_V0(nn.Module):
    def __init__(self, k=256):
        super().__init__()
        self.enc = EncoderV0(k)
        self.dec = DecoderV0(k)
        self.awgn = AWGNChannel()

    def forward(self, x, snr_db):
        s = self.enc(x)            # ① 编码 (B,3,32,32)→(B,k)
        s = power_norm(s)          # ② 功率归一化
        y = self.awgn(s, snr_db)   # ③ 过信道 y=s+n

2.7 训练循环：五件套跑起来

算法 2-4 · 训练一步每个 batch 固定五连：forward → loss → 清零 → 反传 → 更新
\mathcal{L} = \text{MSE}(\hat{x}, x) = \dfrac{1}{N}\textstyle\sum_i (\hat{x}_i - x_i)^2

重建任务的损失就是「逐像素差方平均」。你在 YOLO 源码里见过不同版本的检测损失组合（不可把旧版含 DFL 的组合套给所有 YOLO 版本）——JSCC 只有一项，简单得多。梯度会从 loss 一路穿过解码器、穿过加噪那一行（每次采一个噪声样本后对计算图求导，跨多次采样近似期望梯度；不是精确计算噪声期望）、流回编码器——「抗噪的编码方式」就是被这个梯度逼出来的。

train_v0.py项目内片段：先自行定义/导入 JSCC_V0，再固定 10dB 训练
import torch
import torch.nn as nn
from torchvision import datasets, transforms
from torch.utils.data import DataLoader

DEVICE = "cuda" if torch.cuda.is_available() else "cpu"

tf = transforms.ToTensor()                    # 只做 [0,1] 归一化，不加 Normalize！
train_set = datasets.CIFAR10("data", train=True, download=True, transform=tf)
loader = DataLoader(train_set, batch_size=256, shuffle=True, num_workers=0)

model = JSCC_V0(k=256).to(DEVICE)
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
loss_fn = nn.MSELoss()

for epoch in range(50):
    total = 0.0
    for x, _ in loader:                       # 标签用不上，JSCC 是无监督重建
        x = x.to(DEVICE)
        snr_db = 10.0                         # 先固定；第 3 章改成随机采样
        x_hat = model(x, snr_db)              # forward
        loss = loss_fn(x_hat, x)              # 重建误差
        opt.zero_grad()                       # 清上一步的梯度
        loss.backward()                       # 反向传播
        opt.step()                            # 更新参数
        total += loss.item()
    print(f"epoch {epoch}  loss {total / len(loader):.5f}")

编码器里 h.reshape(h.size(0), -1) 的 -1 算出来是多少？
4096。总元素 256×4×4=4096，第 0 维固定为 B，剩下的全塞进第二维：(B, 4096)。
opt.zero_grad() 忘了写会出什么现象？
PyTorch 梯度默认累加——每批的梯度叠上历史批次的，等效步长越走越大、方向被旧梯度污染，loss 先降后爆或剧烈震荡。它是五连里最「不报错但毁训练」的一步。
class 里忘了写 super().__init__() 会怎样？
在 self.fc = nn.Linear(...) 那行（或更早）直接报错——父类的参数记账本没搭起来，零件登记不进去。报错长得吓人，病因就一行。
power_norm 里把 keepdim=True 删掉，程序会报错吗？
分情况：B=k 时会按列广播，静默混入别的样本的 RMS；一般 B≠k 且两者大于 1 时会报错；B=1 时可能碰巧算对。必须验证 B=1、B=k、B≠k，并明确期望除数形状是 (B,1)。跑码件的 [0.24,0.32] 演示是除均方值的广播算术，不是最终 RMS 归一化结果。
stride=2 的转置卷积用 4/2/1 组合，4×4 输入输出多大？连过三次呢？
4→8→16→32。这组 (kernel_size=4, stride=2, padding=1)，在 dilation=1、output_padding=0 时就是「边长×2」的组合，跟卷积那组减半互为镜像。
编码器为什么用 stride=2 卷积而不是 pool？
两种都能做。stride=2 卷积让「下采样」本身可训练（pool 是固定规则），JSCC 文献普遍用卷积下采样。本质区别不大，用哪个都能出结果——面试被问就说「文献惯例 + 可训练的下采样对重建更友好」。
k=43（实数 k/n≈1/71.44，n=3072）时 4096→43 的全连接压得这么狠，重建图会怎样？
信息瓶颈变窄，通常更难保留细节；但曲线形状和与 JPEG 的差距必须实测。不同 k 需分别训练并匹配测试预算，不能从示意动画推出结论。
训练循环里 loss_fn(x_hat, x) 换成 loss_fn(x_hat, y)（信道输出）会怎样？
本任务的重建目标是原图 x。先看变量：当前训练片段没有暴露模型内部的 y，直接替换可能先报 NameError。即使取出了信道输出，x_hat 的形状是 (B,3,32,32)，y 是 (B,k)；k=256 时无法广播，MSELoss 会报尺寸不匹配，不能开始这次反传。即便另行改到同形状，训练目标也已改变，不能直接断言一定出现“loss 下降但图变糊”。
为什么本教学模型只把 SNR 提供给解码器？
这是先简化接口的教学选择，不是发送端不能利用 SNR。即使固定总功率，编码器仍可根据信道条件调整特征表示和各分量的相对分配；ADJSCC 的系统模型就同时给编码器和解码器提供 SNR。若扩展到发端条件输入，需要说明 SNR 的获取方式以及反馈等开销。本页只给接收端提供 SNR，让模型有机会随噪声条件调整重建；拼接设计是否提升质量、在哪些 SNR 有效，须与无显式 SNR 的模型公平对照，当前没有完整训练结果可保证增益。

第 3 章SNR 随机化 · 评测 · JPEG 基线

先抓住主线第 2 章解决“能不能训练”；本章解决“怎样证明它有效”。先让模型见过不同噪声，再固定测试条件计算重建误差，最后把传统链路的发送预算算清楚。曲线的高低由实验回答，不能先写结论再凑数据。

3.1 随机 SNR：每一批换一种天气

训练 SNR决定模型平时见到多大噪声；测试 SNR是考场环境。只在 10 dB 训练，好比一直在安静教室听课，换到吵闹站台未必适应。随机训练让同一个模型在若干种环境里练习，但不保证它在每个点都胜过专门训练的模型。

策略这一批做什么测试时怎么做

3.2 PSNR：先平方平均，再取对数

先区分两个“信噪比”：信道 SNR衡量发送符号与信道噪声的功率比，是实验旋钮；图像 PSNR衡量重建误差，是输出成绩。两者都用 dB，但不相等。PSNR 中的峰值 MAX 是像素范围的上限；[0,1] 图像取 1，原始 [0,255] 图像取 255。

算法 3-1 · 一张图的重建分数
e_i=\hat{x}_i-x_i
\mathrm{MSE}=\frac{1}{D}\sum_{i=1}^{D}e_i^2
\mathrm{PSNR}=10\log_{10}\frac{\mathrm{MAX}^2}{\mathrm{MSE}}

符号翻译：x 是原图，x̂ 是重建图，i 是某个颜色通道里的某一格，D=3HW 是一张图参与比较的所有数的个数。MSE 越小，PSNR 越大；PSNR 不直接衡量物体是否被正确识别。

完整小例子：原图四格 [0, 0.5, 1, 0.5]，重建 [0.1, 0.4, 0.8, 0.5]。误差是 [0.1, −0.1, −0.2, 0]，平方是 [0.01, 0.01, 0.04, 0]，MSE=0.06/4=0.015，PSNR≈18.239 dB。这是一张四格玩具图的全部数据，不是某个 batch 的一行摘要。

教学函数 · 输入 (B,C,H,W)，输出每张图的 (B,) 分数
import torch

def psnr_per_image(x_hat, x):
    error = x_hat - x
    squared = error ** 2
    mse = squared.mean(dim=(1, 2, 3))
    return -10.0 * torch.log10(mse)
两个“平均”不是同一个结果两张图的 MSE 分别是 0.01、0.1，各自 PSNR 为 20、10 dB，逐图 PSNR 均值=15 dB。先平均 MSE 得 0.055 再换算，得到约 12.596 dB。两者都是可定义的指标，但不能混用。本页曲线采用逐图 PSNR 的算术平均。若用 clamp 避免 log(0)，要披露阈值及对应的分数上限。

3.3 从一次 forward 到可信的一条曲线

  1. 先划分数据：训练集更新权重，验证集选超参数与检查点，测试集只做最终报告。不能看着测试分数反复挑最好的一轮。
  2. 冻结模型行为：调用 model.eval()；评测放在 torch.no_grad() 或 inference_mode 中。eval 不等于关闭梯度，也不会关闭你自定义信道里的 randn。
  3. 一次只改一个条件：固定权重和 k，测试 SNR 依次取 0、5、10、15、20 dB。每个点遍历同一测试集，噪声重新采样。
  4. 按图累计：对每张图算 PSNR，累加分数并累加图数，最后相除。不要把不同大小 batch 的均值再等权平均，最后一批可能比较小。
  5. 测随机波动：例如预先指定 3 个种子，各完成一次全测试集评测；报告 3 次均值的平均与标准差。控制数据顺序、种子与噪声形状；精确配对比较时复用显式生成的噪声。同一整数种子不保证不同架构消耗随机数的方式相同。
  6. 留下证据：记录模型名、检查点、实数符号数 k、SNR 定义、信道、CSI 假设、测试集、种子、逐图均值 PSNR、重复次数和标准差。CSV 一行对应一个明确实验条件。

C 类比：统计就是 sum += 每张图的分数; count += 图数;，最后 sum/count。测试协议像通信实验的仪器设置，换旋钮之前先固定其余条件。

3.4 JPEG+BPSK：先数用了多少次信道

JPEG 输出字节，BPSK 输入比特，JSCC 输出连续实数。三者不能直接比长度。本教程统一按“实数信道使用次数”记预算：JSCC 发送 k 个实数就是 k 次；无编码 BPSK 每比特需要一次。

算法 3-2 · 无编码 BPSK 的发送账
L=\operatorname{len}(\text{JPEG bytes}),\qquad K_{\mathrm{BPSK}}=8L

例如某张 JPEG 实测 700 字节，就需要 5600 次 BPSK 发送；本页 JSCC k=256 只发 256 次，不能把二者称作等带宽。加上 CRC、纠错编码和帧头后还会增加开销；码率 R=1/2 意味着每个信息比特大约对应两个编码比特。

对象玩具数字如何判断
JSCCk=256 次实数使用固定预算 256
JPEG＋无编码 BPSKL=700 字节 → 5600 次超预算，不能硬画在“等预算”对比里
可容纳的 JPEG256/8=32 字节连常规 JPEG 文件头都可能容不下；质量因子再低也不保证可行

正确处理“不够装”：预先确定预算，在合法质量因子中实测文件大小；若没有任何完整码流符合预算，记录 infeasible（不可行）。不能截断字节伪装预算满足，也不能偷偷给 JPEG 更多信道使用次数。先用较大图或较宽预算做可行的教学比较；固定 32×32 的 V0 处理大图时要按分块数乘 k。

BPSK 的 3 dB 口径坑本页实数信道用 γ=P/σ²；传统 BPSK BER 图常用 γᵦ=Eᵦ/N₀。单位能量 BPSK、实维噪声方差 σ²=N₀/2 时，γ=2γᵦ，因此本页 SNR(dB)=Eᵦ/N₀(dB)+3.0103。复用单元 4 代码前先检查横轴和噪声公式，不能只把变量改名。

3.5 JPEG 基线链路：失败也属于结果

  1. 原图编码成完整 JPEG 字节，记录字节数、质量因子、色度采样及帧开销。
  2. 字节拆成比特，映射 0→+1、1→−1。注意 NumPy 的 uint8：先转浮点再算 1.0 - 2.0 * bits，避免负数回绕。
  3. 按同一种实数 SNR 定义加噪，接收值小于 0 判为 1，再按原顺序拼回字节。
  4. 用解码器完整加载图像；解码可能抛错，也可能成功但图已受损。若实验定义了 CRC，则按 CRC 规则判失败，且开销计入预算。
  5. 预先约定失败图的替代规则，例如输出全 0.5 灰图，然后与原图计算 PSNR；同时报告解码失败率，不能只平均成功图片。

实验级别要写明：JPEG＋无编码 BPSK 是理解码流脆弱性的入门基线。它没有 LDPC 等纠错保护，不能代表所有传统通信系统。要研究强分离式方案，应加入明确的纠错编码与码率，或单列“理想容量基线”并披露理想假设。不能用人为设置的 5 dB 崩坏门限替代实验。

4.1 图像怎么变成 64 个 token

翻译模型的 token 是词表中的编号；这里的 token 是一小块图像投影得到的向量。patch 就是“小块”：32×32 图像按 4×4 不重叠切块，每行 8 块，共 8×8=64 块。每块有 RGB 三个通道，因此一块带 3×4×4=48 个数。

记号本章数值含义
B例如 2一批图像数
p4小块边长，不是块的数量
N(32/4)²=64每张图的 token 数；与第 1 章 n=3072 区分
d64一个 token 的特征维度；不表示信道发送了 64 个符号
k256最终真正过信道的实数个数

别把“块”和“块内元素”混在一起：完整批形状依次是 (B,3,32,32) → (B,64,48) → (B,64,64)。其中第二个轴始终是“第几块”，第三个轴从 48 个原始数变成 d=64 个特征数。

4.3 投影与位置：告诉网络“这块在哪”

每块 48 个数经过同一个 nn.Linear(48,64)，变成一个 64 维 token。共享的意思是 64 个块使用同一套权重，不是各自造一个 Linear。这与词表 Embedding 查行不同：图像 patch 是连续数，需要做矩阵乘法。

算法 4-1 · 第 j 块变 token
t_j=Wq_j+b
u_j=t_j+e_j

qⱼ 是 48 维小块，W 是 64×48 权重，b 是 64 维偏置，eⱼ 是“第 j 块”的 64 维位置向量。位置表形状 (1,64,64)，与整批 (B,64,64) 相加，最前面的 1 广播到 B。

两维手算：把真实 48→64 缩成 2→2 玩具：q=[1,2]，W 两行是 [1,0]、[1,1]，b=[0,0]，则 t=[1,3]。若该位置向量 e=[0.1,−0.2]，u=[1.1,2.8]。位置是在特征上相加，不是额外增加一个 token。

4.4 Attention 在这里看的是图像块

令 d=64、头数 h=4，每头维度 dₕ=16。完整形状：输入 (B,64,64)，Q/K/V 拆头后各为 (B,4,64,16)，注意力分数为 (B,4,64,64)。最后两个 64 的身份不同：行=发起查询的块，列=被关注的块。例如第 0 行第 9 列表示“左上块从第 9 块取多少信息”。

算法 4-2 · 每个头内部的三步
S=QK^\mathsf{T}/\sqrt{16}
A=\operatorname{softmax}(S)\quad\text{（沿 key 列）}
O=AV

先算相似度，再把每一行归一成权重，最后按权重混合 V。这里每一行对应一个 query patch；softmax 沿最后一维，不是跨 batch 归一化。

一个小头的具体计算：若某 query 对两个 key 的缩放分数是 [0, ln 3]，softmax 得 [0.25,0.75]；两行 V=[2,0] 与 [0,4]，这个 query 输出就是 0.25[2,0]+0.75[0,4]=[0.5,3]。这是一个 query 行的局部例子，完整注意力表仍有 N 个 query 行。

图像重建一次可以看到全部收到的信息，不需要翻译任务的 causal mask（遮未来）。每张图固定 64 块，也没有变长句子的 PAD。本教学方案的两端都可使用自注意力 encoder block；“接收端解码器”是通信系统的职责名称，不意味着必须调用带 cross-attention 的 nn.TransformerDecoder。

局部层实验 · 只看接口，不是完整 V1

block = nn.TransformerEncoderLayer(
    d_model=64, nhead=4, dim_feedforward=128,

4.4.1 接回你学过的完整 Transformer block

上面的代码把整块封装起来了。把它打开，Pre-LN 的顺序如下。令输入 T 的形状为 (B,N,d)=(2,64,64)，先不考虑 Dropout（局部例子设为0）。

顺序怎么计算形状与目的
1 · 归一化U = LayerNorm(T)(2,64,64)；分别归一每个token最后一维的64个特征
2 · 多头注意力A = MHA(U,U,U)(2,64,64)；三个U经各自投影成为Q/K/V，混合不同图块的信息
3 · 第一次残差R = T + A(2,64,64)；保留输入，也加入注意力更新
4 · 再归一化V = LayerNorm(R)(2,64,64)；使用第二套LayerNorm参数
5 · 前馈网络F = Linear₂(ReLU(Linear₁(V)))(2,64,64) → (2,64,128) → (2,64,64)，逐token处理
6 · 第二次残差输出 = R + F(2,64,64)；块外形状不变，可以接下一个独立block

三个容易混的64：N=64是图块数；d=64是每块特征宽度；单头关系表恰好也是64×64，因为每个query块都要和每个key块配对。头数4不是把64个图块分成四组，而是把每个图块的特征投影后拆成4份，每头仍看全部64块。

本例没有传 activation 参数，PyTorch 默认用 ReLU；若改成 GELU，要记录这是另一处配置变化。注意力在块与块之间交换信息，FFN则对每个块使用同一套非线性变换。两条残差都在各自一端内部，不能跨越噪声信道把干净特征送到接收端。

4.5 真正的瓶颈：4096 个特征 → k 个发送数

64×64=4096 个 token 特征不能全部偷偷传过去。编码器末尾把它们展平成 (B,4096)，再用 Linear(4096,k) 压成 (B,k)，之后复用第 1 章功率归一化和信道。编码器内部 d=64，并不等于发送预算 k。

4.6 自己实现时，按这四步验收

  1. 先验证坐标：用 0–15 的小图做 patchify→unpatchify，要求逐元素完全相同。位置错了，loss 也可能下降，所以不能只看曲线。
  2. 只打印形状：先 batch=2，逐层对上 4.5 表。nhead 必须整除 d；编码器和解码器各层参数应按设计独立创建，别用列表重复同一个模块对象而意外共享权重。
  3. 再检查梯度：先用无噪信道检查前向与反传，确认编码器梯度有限且非零，再恢复 AWGN。训练中没有 detach/no_grad 把链截断。小批过拟合用于排查组装，不用于报告泛化性能。
  4. 最后比较 V0/V1：同样 k、功率、SNR、数据划分、训练预算与测试协议，另列参数量、耗时。改 k 会改变全连接权重形状，当前结构需要为不同 k 分别训练；不能拿同一检查点随意切 k。

为什么不能只插值位置表就传大图：32×32 有 64 个 token，展平长度 4096；若变成 64×64，就有 256 个 token、展平长度 16384。即使位置表插值成功，Linear(4096,k) 仍接不住 16384。当前先采用第 3 章分块测试；支持任意尺寸要另设计瓶颈与符号预算，属于后续模型改造。

4.7 让接收端 Transformer 知道“现在有多吵”

先想一个接收机：听到含糊声音时，你可能更多结合上下文；声音清楚时，更依赖当前观测。神经网络也可以把噪声水平作为条件，学出不同的特征处理方式。但“噪声大时应该放大哪一维”没有人工固定答案，需要从训练数据里学。

第 2 章和 V1-base 已经把两个 SNR 特征拼到接收向量末尾。本节保留这个接口，只新增一处逐特征维度的缩放：接收向量恢复成 token，加好接收端位置表，然后缩放，再进入第一个接收端 Transformer block。

y + 两个 SNR 特征 → Linear → reshape 为 (B,N,d)
→ 加接收端位置表 → [本节新增：SNR 门控] → 接收端自注意力 → 像素
机制它看什么它产生什么
图块自注意力当前各个 token 的内容每个头 N×N 的图块关系权重

这里“特征通道”指 token 向量的第几个分量，不是无线信道，也不是 RGB 三色通道。门控不会增加或减少 token 数，更不会把 k=256 自动变成另一种码率。

4.7.1 先分清真实 SNR 和接收端知道的 SNR

第一轮实验假设估计准确，令两者相等。以后做估计误差实验，必须固定真实加噪条件，只改输入给网络的估计值。例如实际 10 dB、估计 0 dB；不能因为告诉网络 0 dB，就连实际噪声也改成 0 dB。

本节只在接收端加门控，因此不额外要求发送端取得 SNR。若以后把门控也放到发端，就需说明反馈或其他信道信息来源，并计入相应开销。理想已知 SNR 是仿真假设，真实系统估计通常需要资源。

4.7.2 一行乘法，先用两块、四维手算

算法 4-3 · 先缩放条件，再缩放特征
r=(\widehat{\gamma}_{\mathrm{dB}}-10)/10

r 是给小网络看的输入。0、10、20 dB 分别变成 −1、0、1；这只是输入预处理，不是信噪比单位换算。中心与尺度预先固定，不能按测试集临时重算。

g=1+0.5\tanh(\operatorname{MLP}(r))

MLP 是小型全连接网络，输出 d 个数；tanh 把它们限制在 −1 与 1 之间，所以 g 在 0.5 与 1.5 之间。这些范围是本页选择的教学设计，不是论文最佳值。

\widetilde T_{b,j,c}=T_{b,j,c}\,g_{b,c}

b 是第几张图，j 是第几块，c 是第几个特征。对一张图，g 沿 j 复用，形状 (B,d) → (B,1,d) → 广播到 (B,N,d)。

先把学出来的 MLP 换成手工规则练乘法：r=(SNR_est−10)/10，a=[1,−1,0,0.5]，g=1+0.5ra。估计为 0 dB 时 g=[0.5,1.5,1,0.75]；第一块 [2,−1,0,4] 就变成 [1,−1.5,0,3]。这套手工规则仅在演示范围 0–20 dB 使用，不能由它断言重建变好了。

4.7.3 把手工系数换成可学习的小网络

下面仍然只是一块局部零件。先让缩放系数全为 1，相当于“原样通过”；之后把它注册为模型子模块，由同一个重建 MSE 更新它的参数。正式模型中需在初始化阶段创建并登记门控，随模型移动到同一设备；不要在每次 forward 里重新创建。不同图片的 SNR 要保留为 (B,1)。

新 API读法
nn.Sequential按顺序执行一组层；gate[2] 取第 3 个零件，即第二个 Linear
nn.Linear(in,out)只变最后一维；参数数量是 in×out+out（含偏置）
nn.ReLU / nn.Tanh前者保留正数、负数变零；后者平滑压入 (−1,1)
nn.init.zeros_原地把权重或偏置设为零；这里仅用于初始化末层
torch.allclose比较两个张量是否在数值容差内一致，返回布尔值
局部门控零件 · 初始为恒等变换
import torch
import torch.nn as nn

d = 64
gate = nn.Sequential(
    nn.Linear(1, 16), nn.ReLU(),
    nn.Linear(16, d), nn.Tanh())
nn.init.zeros_(gate[2].weight)
nn.init.zeros_(gate[2].bias)
tokens = torch.randn(2, 64, d)
snr_est = torch.tensor([[0.], [20.]])
r = (snr_est - 10.0) / 10.0
g = 1.0 + 0.5 * gate(r)
adjusted = tokens * g.unsqueeze(1)
print(adjusted.shape)
print(torch.allclose(adjusted, tokens))
torch.Size([2, 64, 64])
True

参数账：第一层 1×16+16=32；第二层 16×64+64=1088；总共 1120 个参数。ReLU 和 Tanh 没有可训练参数。新增参数需要进入优化器；只生成系数而没有把门控注册到模型里，训练就不会按预期更新它。

门控与归一化，别凭直觉下结论这里做的是接收端特征缩放，不是增加发射功率。若在发端把所有符号一起乘同一个正数，后续功率归一化会消掉这一倍率（忽略 eps 的微小影响）。LayerNorm 也会抵消整体缩放的很大一部分，因此本设计使用逐维系数；它放在 Pre-LN block 前时还会影响残差支路。是否有效只能通过对照实验判断。

为什么第一步里某些梯度恰好为零：末层权重初始化为零，第一次反传时前一层的梯度可能为零；末层先得到更新，后续梯度才能继续影响前一层。不要把“第一步所有层都必须非零”当验收条件。应检查梯度有限、未被 detach 截断，并确认若干次更新后门控能变化。冻结权重与切断输入梯度也不是同一件事。

4.8 patch 改小了，究竟多花在哪儿

仍是同一张 32×32 RGB 图，固定 d=64、h=4。p 是小块边长，N=(32/p)² 是块数。改 p 同时改变 token 数、每块像素数和展平长度，当前 V1 的瓶颈参数也会跟着变。

算法 4-4 · 三笔不同的预算
N=(32/p)^2,\quad D=Nd

D 是进入展平瓶颈的特征总数；源分量数 n_source=3×32×32=3072 始终不变。

\text{单图单层注意力分数数目}=hN^2

这是关系表的元素数，不是整个模型的 FLOPs 或显存；实际注意力实现可能不显式存整张表。

P_{\mathrm{bottleneck}}=(Dk+k)+((k+2)D+D)

前一项是发送 Linear(D,k)，后一项是接收 Linear(k+2,D)，两项都含偏置；这里不统计其他层。

  1. 先固定 k：比较 p=2/4/8，在相同信道使用次数下记录质量、完整参数量与耗时。这是“整套配置”对比，不能声称只改变了局部感受野。

4.9 怎样做对照，才能知道改进来自哪里

先只选 AWGN、p=4、k=256。把基础模型与训练流程跑稳以后，再扩展维度。这里的“消融”就是每次拿掉或加入一个组件，看指标变化，避免同时更换骨干、损失和信道。

实验名结构与条件主要比较
V0CNN；接收端拼接两个 SNR 特征作为已有基线
V1-base基础 Transformer；同样拼接条件与 V0 比较结构、质量和开销
V1-gate与 V1-base 相同，再加一处接收端门控条件调节有没有增益，值不值额外开销
V1-constant（后做）保留门控网络，输入固定条件；原有拼接仍用真实估计值与 V1-gate 比较，区分动态门控和新增参数的作用

V1-constant 仍能学到固定缩放，因此不是“完全没有门控”。如果想测试网络整体是否需要 SNR，必须另外同时处理拼接和门控两条路径，不能只删掉一条就称为无 SNR 模型。

  1. 保持同一数据划分与训练设置：随机 SNR 范围、优化器、更新次数、检查点选择规则相同；超参数按验证集选，测试集不参与挑选。额外报告训练耗时，不能把相同步数误称为相同计算成本。
  2. 主曲线：测试 SNR=0/5/10/15/20 dB，逐图 PSNR 聚合规则沿用第 3 章；同时记录重建样图、参数量与推理时延。
  3. 重复来源写清：重复训练种子反映训练波动，固定检查点重复信道噪声反映信道随机性，两者分开报告。有条件时做 3 个训练种子；只有一个时如实注明。
  4. 配对噪声：相同 k 的比较尽量复用显式生成的同一噪声张量。仅设置相同随机种子，未必能保证不同代码消耗随机数后仍得到相同噪声。
  5. 测耗时：同设备、分辨率与 batch，先预热；GPU 计时前后同步。分别报编解码器耗时，说明是否计入传输，不能直接与别人在另一块 GPU 上的毫秒数比较。

建议每行实验记录保存：模型名、训练种子、检查点、p/d/头数/层数/k、实数符号口径、SNR_true、SNR_est、测试噪声种子、PSNR、完整参数量、batch 与设备、编解码毫秒数。没有测到的列留空并注明，不填预期值。

4.9.1 基础结果出来后，再做一次“信道信息告诉错了”

把真实 SNR 固定为 10 dB，把接收端估计分别设为 5、10、15 dB。拼接与门控都接收同一个错误估计，信道仍按 10 dB 加噪。如果模型依赖精确信息而明显退化，再考虑训练时扰动估计值；这时 V1-base 与 V1-gate 都要有对应训练对照。它是本页后续实验建议，没有预先保证鲁棒性提升。

结果没有变好，也可以得到可靠结论若 gate 没涨分，检查它是否更新、两条条件输入是否重复、当前任务是否已经足够简单；若涨分却显著变慢，把这个代价报出来。V1 没赢 V0 时保留结果，分析参数、优化和数据范围，不把“Transformer 一定更强”作为验收标准。

为什么先学基础 Transformer，再看 Swin：当前 32×32 教学例子只有 64 个 token，容易逐轴检查。大图全局注意力的关系表迅速增长；Swin 使用局部窗口、移位窗口与层级特征，结构更复杂。窗口大小、patch 大小和层级合并是不同概念，不要把 patch 改大就称作 Swin。

后续顺序：基础 V1 → 单处接收端 SNR 门控 → patch/k 对照 → 再按需要学习 Swin 层级结构或单模型变码率。当前固定 k 的模型改 Linear 后重训，只是多种固定预算实验；要做单模型变码率，需要专门的训练与接收接口，不能截短现有输出冒充。

这些工作提供方法依据，不提供你模型的成绩。没有完成训练前，不给 V1 写上“领先多少 dB”；SNR 门控、Transformer 骨干也都是已有研究方向，复试应讲清你亲手实现了什么、验证了什么。

4.11 学到这里，用六个问题收尾

① 为什么 3072 个像素分量先变成 4096 个特征，还能叫压缩传输？
内部特征可以更宽；最后只发送 k=256 个实数。压缩预算看穿过信道的量，不看中间层最大维度。
② tokens=(2,64,64)，g=(2,64)，为什么不能直接相乘？
广播从末维向前对齐，第二轴会遇到64与2不兼容。应把g变成(2,1,64)，让每张图自己的64维系数复用到64块；不能依赖某些相等尺寸碰巧不报错。
③ 门控 1120 个参数，为什么发送符号仍然是256个？
1120是存储在接收模型里的权重数量，不是每张图要发送的数据。它只处理收到的特征，不改变k；真实系统另需说明模型部署与SNR估计成本。
④ 把实际10 dB告诉网络为5 dB，应该改哪两处、保持哪一处？
拼接特征和门控都使用5 dB估计；信道噪声继续由真实10 dB生成。不要在同一次实验偷偷把两条路径中的一条留成完美信息。
⑤ p从4变2，关系表为什么增至16倍，而不是4倍？
N从64变256，是4倍；每个query都和每个key配对，所以N²是16倍。完整模型的计算和显存还包括投影、FFN和瓶颈，不能都按16倍估计。
⑥ 只换一个SNR门控，就能说复现了SwinJSCC吗？
不能。骨干、窗口与层级结构、调制模块、预算和训练协议都需要逐项对应。本页V1是受文献启发的教学设计。
